## Código, datos y recursos

El README original separa MIT de datos geográficos: NYC Open Data, entradas de metro MTA y OpenStreetMap/ODbL. No afirmar que todo el repositorio, todos sus datos y cualquier recurso añadido comparten MIT.

La nueva escena puede prescindir de geodatos de Nueva York. Mientras sigan en el repositorio o una distribución, conservar sus atribuciones y revisar sus términos. Crear un escenario ficticio no elimina obligaciones de recursos copiados.

Three.js, Rapier, fuentes, modelos, texturas y audio necesitan inventario de versiones y licencias reales al incorporarse. No completar el registro con licencias inferidas únicamente del nombre del paquete.

## Registro de terceros propuesto

| Campo | Contenido requerido |
| --- | --- |
| ID | Identificador interno |
| Recurso y versión | Nombre exacto, hash o release |
| Autor y URL | Fuente verificable |
| Licencia | Archivo o enlace al texto aplicable |
| Uso y modificaciones | Dónde aparece y qué se cambió |
| Redistribución | Archivos incluidos y atribución requerida |
| Estado | Pendiente de revisar / revisado |

Crear THIRD_PARTY_NOTICES en una fase de implementación cuando se identifiquen las dependencias reales. Esta tarea no modifica archivos fuera de docs.

## Referencias creativas

Trailmakers inspira construcción y experimentación. No copiar modelos, interfaz, música, nombres, personajes ni código sin permiso aplicable. La identidad del taller y los recursos propios deben registrarse por separado.

## Criterio para publicar

No distribuir un recurso de procedencia desconocida. Mantener créditos accesibles y avisos requeridos en la compilación. Revisar recursos provisionales antes de producir imágenes públicas o builds. Las obligaciones dependen del recurso y su uso, no de que el juego sea gratuito.
